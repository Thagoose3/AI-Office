# โปรเจกต์: <ชื่อโปรเจกต์> (อ่านก่อนทำงานทุกครั้ง)

> แก้ไฟล์นี้ให้ตรงกับโปรเจกต์ของคุณ ทุก role จะอ่านไฟล์นี้ก่อนเริ่มงาน

<อธิบายสั้นๆ ว่าระบบนี้คืออะไร ใครใช้> · ที่อยู่: `<path ของโปรเจกต์>`

## โครงสร้าง
- <เช่น `src/` โค้ดหลัก, `server/` API, `public/` ไฟล์ static>

## เขตงาน (กันแก้ไฟล์ชนกัน)
- **dev**: <ไฟล์ฝั่ง server / logic / database>
- **ui**: <ไฟล์หน้าจอ / component / CSS>
- ไฟล์ที่สองฝ่ายอาจต้องแตะ ให้แชทกลางกำหนดว่ารอบนี้ใครแก้ ห้ามสองคนแก้ไฟล์เดียวกันพร้อมกัน
- **tester**: ไม่แก้โค้ด

## คำสั่งตรวจก่อนบอกว่าเสร็จ
- <เช่น `npm run build`, `npm test`, `npx tsc --noEmit`>

## ข้อห้าม (ทุก role)
- ห้ามแก้หรือลบฐานข้อมูล / ไฟล์ข้อมูลจริงตรงๆ
- ห้ามใส่รหัสผ่าน / token / ข้อมูลลับลงในโค้ด และห้าม commit `.env`
- ห้ามปิดหรือลดระบบความปลอดภัย (auth, สิทธิ์ผู้ใช้, audit log) เพื่อให้งานผ่านง่ายขึ้น
- ห้ามบอกว่าเสร็จถ้ายังไม่ได้รันคำสั่งตรวจจริง และห้ามปิดบังสิ่งที่ข้ามไป
- ห้าม `git push` ถ้าผู้ใช้ไม่ได้สั่ง

## git
commit แยกต่องาน ข้อความแบบ `[TASK-03] สิ่งที่ทำ`

## ไฟล์สื่อสาร (`.review/`)
- `TASKS.md` งานจาก PM / `REVIEW.md` ผลตรวจจาก PM (แก้ได้เฉพาะ role pm)
- `HANDOFF.md` แชทกลางรายงานงาน / `TEST_REPORT.md` tester รายงานผลทดสอบ

## รายงานสถานะออฟฟิศ (ทุก role)
เขียนทับไฟล์ `.office/status/<role>.json` ของตัวเองเท่านั้น เมื่อเริ่มงาน, ขึ้นขั้นตอนใหม่ (อย่างน้อยทุก ~10 นาที), ติดปัญหา, เสร็จงาน
```json
{"agent":"dev","state":"working","task":"TASK-01","doing":"สิ่งที่กำลังทำ สั้นๆ","progress":40,"updated":"<เวลาปัจจุบัน ISO เช่น 2026-11-06T14:45:00+07:00>"}
```
state: pm → `planning`/`reviewing` · dev → `working` · ui → `designing` · tester → `testing` · ทุกคน → `blocked` (ติด) / `idle` (เสร็จหรือไม่มีงาน)
